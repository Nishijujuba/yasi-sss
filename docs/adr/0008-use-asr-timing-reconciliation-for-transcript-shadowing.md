# Use ASR Timing Reconciliation For Transcript Shadowing

Transcript Alignment will use ASR Timing Reconciliation as the primary workflow for producing Transcript Word Timings. The default ASR timing source is the local Whisper CLI with word timestamps enabled; `transcript.json` remains the Transcript Text Authority, and reconciliation maps ASR tokens onto official transcript token identities before final timing verification.

This supersedes ADR-0007 because the Qwen forced-alignment path can stall even after localization and short slicing, while timestamped ASR evidence can still support shadowing when official text authority, review trace, and release gates remain strict.

## Considered Options

- Continue with Qwen direct forced alignment: preserves a tool-specific alignment model, yet Section 01 has already shown timeout behavior across full, 180-second, 60-second, and 15-second attempts.
- Keep ASR only for localization before Qwen: keeps the previous boundary, yet still depends on the stalled forced-aligner stage for the final word times.
- Display ASR text directly: fastest path to timed text, yet it violates Transcript Text Authority and can change spellings, numbers, names, currency, and answer-bearing words.
- Use ASR Timing Reconciliation with local Whisper word timestamps: uses ASR word times as timing evidence, official transcript tokens as final identity, and review trace for risky or inferred mappings while avoiding the stalled Qwen model path.

## Consequences

The new `.agents/skills/yasi-asr-timing-reconciliation/` skill should own Whisper ASR generation, token reconciliation, interpolation rules, review artifact generation, run-level reporting, review screening, and final `transcript-timings.json` validation. Its working artifacts live under `D:\Project\yasi\待删除\yasi-asr-timing-reconciliation\`, grouped by section and model for temporary evaluation and review. The stable ASR evidence artifact is named `asr-timing-evidence.json`; it records engine, model, command, source audio identity, and word timestamps. The stable run report is named `reconciliation-report.json`; it records match statistics, review burden, highest-risk regions, provenance, and a three-state gate outcome: `ready-for-finalize`, `needs-review`, or `rerun-asr`. Section 01 benchmarking did not produce a release-ready automatic default because every candidate exceeded the pending-review gate, yet `small` is the default generation model because it had the same or lower review burden than larger candidates and the fastest runtime. This default is a generation default only; release still requires review screening, resolved review decisions, and validation. The default token mapping algorithm is sequence alignment over normalized ASR and official tokens, followed by exact anchor extraction and bounded interpolation across gaps. Automatic interpolation is allowed only for gaps of at most 3 official tokens, with surrounding anchors at most 2.5 seconds apart, and no high-risk or answer-near token inside the gap. Review artifacts must classify each uncertain or provenance-bearing mapping with `matchType: exact | fuzzy | interpolated | split | merged | unmatched`. Review screening may auto-approve exact normalized mappings with valid timing and no structural risk, may create LLM-assisted suggestions for textual fuzzy or compound mappings, and must keep numbers, currency, spelling sequences, missing timing, unmatched tokens, and invalid timing human-gated. Blind LLM pre-review may label every unresolved item before human listening, while deferred auditory review must wait until the learner has submitted the section or explicitly entered Transcript Shadowing. Benchmark review artifacts remain temporary, while the `alignment-review.json` used to produce a released verified `transcript-timings.json` must be promoted under `build/review/transcript-timing/` as the durable Transcript Timing Release Audit. Release validation must require `transcript-timings.json.reviewArtifact` to be a repo-root-relative path pointing to that durable audit artifact, verify that it exists, and reject pending or missing required review coverage. The final frontend contract remains `transcript-timings.json` with schema `yasi.transcript-timings.v1`; ASR engine, confidence, token alignment, interpolation, and review provenance belong in temporary generation artifacts and release audit artifacts, then only verified Transcript Word Timings enter the pack asset. Windows runners should set `PYTHONUTF8=1` when invoking Whisper, and the primary workflow should not load Qwen models. The old `yasi-forced-alignment` skill remains historical context and a source of reusable artifact and validation ideas, while ADR-0007 records the superseded Qwen slicing approach.
